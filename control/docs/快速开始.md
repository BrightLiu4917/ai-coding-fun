# 快速开始

## 一句话说明

这套工具不是业务框架，也不是运行时服务。它是复制到项目根目录里的 AI 开发控制系统，用来约束 Codex 按“需求确认 -> 设计 -> 实现 -> 测试 -> deepv4 二审 -> 最终校验”工作。

## 第一次接入

在控制系统仓库执行：

```bash
bash control/scripts/setup-control-system.sh
```

按提示输入目标项目目录。脚本会自动识别项目类型，生成：

```text
.ai-control/project.env
.ai-control/project-profile.md
```

然后安装 OpenSpec、agents、docs、scripts、templates 等控制文件。

## 小白模式

进入目标项目后，只需要记住一个入口：

```bash
bash .ai-control/control/scripts/ai-dev.sh init
bash .ai-control/control/scripts/ai-dev.sh feature login-jwt
bash .ai-control/control/scripts/ai-dev.sh ready login-jwt
bash .ai-control/control/scripts/ai-dev.sh test
bash .ai-control/control/scripts/ai-dev.sh review
bash .ai-control/control/scripts/ai-dev.sh next
```

- `init`：生成最小项目卡片，不要求一次写完整背景。
- `feature`：创建某个功能的 OpenSpec 骨架。
- `ready`：检查是否可以进入代码实现。
- `test`：运行测试。
- `review`：准备并运行 deepv4 二审。
- `next`：告诉你下一步该做什么。

不安装官方 OpenSpec CLI 也可以使用这套流程。`ai-dev.sh` 会直接创建和检查本地 `openspec/` 目录。

如果你额外安装了官方 OpenSpec CLI，可以在新项目接入前运行 `openspec init`；已经安装本控制系统后，不建议盲目再次运行，先提交或备份再看 `git diff`。

`init` 会让你用编号选择访问控制模式，不需要手写英文：

```text
1) 本服务建设 RBAC
2) 外部系统负责权限，如网关、IAM、SSO 或统一权限服务
3) 不适用
4) 待确认
```

`init` 还会询问是否现在启用 deepv4。选择启用后直接输入：

```text
DEEPV4_BASE_URL
DEEPV4_API_KEY
DEEPV4_MODEL
```

脚本会生成 `.agent/deepv4.env`，真实 key 不会写入 `openspec/`、`.ai-control/control/docs/` 或 `.ai-control/`。

如果项目已经初始化过，`init` 默认不会覆盖已有文件，也不会静默修改 `.ai-control/project.env`。需要重写项目卡片或访问控制模式时再加：

```bash
bash .ai-control/control/scripts/ai-dev.sh init --force
```

## 非交互式接入

适合已经知道项目目录时使用：

```bash
bash .ai-control/control/scripts/bootstrap-new-project.sh --project-dir /path/to/project
```

脚本默认使用 `--profile auto` 自动识别项目类型。

指定 profile：

```bash
bash .ai-control/control/scripts/bootstrap-new-project.sh \
  --project-dir /path/to/project \
  --profile fullstack-admin \
  --deepv4
```

## 接入后检查

进入目标项目根目录：

```bash
bash .ai-control/control/scripts/check-project-ready.sh
```

再按需执行：

```bash
bash .ai-control/control/scripts/agent-check.sh
bash .ai-control/control/scripts/docs-link-check.sh
bash .ai-control/control/scripts/run-tests.sh
```

## 第一个需求怎么说

先用命令创建功能：

```bash
bash .ai-control/control/scripts/ai-dev.sh feature login-jwt
```

如果这个 change 已经存在，默认会跳过已有文件。需要重生成骨架时：

```bash
bash .ai-control/control/scripts/ai-dev.sh feature login-jwt --force
```

然后把命令输出的提示复制给 Codex。示例：

```text
我要做 JWT 登录系统。先走 OpenSpec，不要直接写代码。
请设计能力边界、表结构、API、权限、JWT 策略和需要我确认的问题。
```

确认 OpenSpec 后再说：

```text
我已确认 openspec/changes/login-jwt。
请按 tasks.md 最小可验证切片实现。
实现后运行 bash .ai-control/control/scripts/ai-dev.sh test。
```

## 常用文件

| 文件 | 用途 |
|------|------|
| `AGENTS.md` | AI 工作总规则 |
| `.ai-control/project.env` | 项目画像，非密钥，可提交 |
| `.agent/project.env` | 本机覆盖配置，不提交 |
| `.agent/deepv4.env` | deepv4 密钥配置，不提交 |
| `openspec/` | 需求、设计、任务和规格事实源 |
| `openspec/project.md` | 项目定位、技术栈、角色、API 规则和访问控制模式 |
| `CONTEXT.md` | 领域术语、状态候选和不能猜测的规则 |
| `.ai-control/control/agents/` | 中文角色手册 |
| `.ai-control/control/docs/` | 工程规则 |
| `.ai-control/control/scripts/` | 检查、测试和二审脚本 |
