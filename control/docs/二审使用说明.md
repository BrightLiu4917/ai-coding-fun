# 二审使用说明

## 定位

独立二审只做二审，不直接写代码，不决定业务规则。

推荐分工：

```text
AI 助手：需求、OpenSpec、架构、实现、测试、最终校验
独立二审：审查 diff、测试结果、SQL、权限、安全、边界和遗漏
AI 助手：判断独立二审意见是否成立，并修复真实问题
```

## 配置

小白优先使用初始化命令配置：

```bash
bash .ai-control/control/scripts/ai-dev.sh init
```

当脚本询问是否启用独立二审时选择启用，然后输入：

```text
REVIEW_BASE_URL
REVIEW_API_KEY
REVIEW_MODEL
```

脚本会生成 `.agent/review.env`。

高级用户也可以手动配置。

在目标项目创建：

```text
.agent/review.env
```

可以从模板复制：

```bash
cp templates/review.env.example .agent/review.env
```

填写：

```bash
REVIEW_BASE_URL='https://api.example.com/v1'
REVIEW_API_KEY='replace-with-your-key'
REVIEW_MODEL='your-model-id'
REVIEW_PROVIDER='openai-compatible'
```

真实 key 不要提交。

## 二审模型的四种接法

| REVIEW_PROVIDER | 说明 | 需要什么 |
|---|---|---|
| `openai-compatible`（默认） | 任何 OpenAI 兼容端点：DeepSeek、Kimi、通义、GLM、GPT、Ollama | BASE_URL + API_KEY + MODEL |
| `anthropic` | Claude 官方 Messages API | ANTHROPIC 端点 + API_KEY + MODEL |
| `claude-cli` | 本机 Claude Code 无头模式（`claude -p`），复用订阅免 API key | 已安装 claude 命令 |
| `codex-cli` | 本机 Codex 非交互模式（`codex exec`），复用订阅免 API key | 已安装 codex 命令 |

CLI 接法每次调用都是全新无状态会话，与实现会话天然隔离，独立性有保证。

没有 CLI 也没有 API 的工具（如 WorkBuddy）走手动：运行 `prepare-review.sh` 生成 `.agent/reviews/review-input.md`，整份粘贴给任意 AI 应用，把回复存为 `.agent/reviews/review-output.md` 归档。

**独立性原则**：二审员不能是写代码的那个会话。实现和二审至少要用不同实例，最好不同厂牌模型。

## 审查流程

实现和测试后执行：

```bash
bash .ai-control/control/scripts/prepare-review.sh
bash .ai-control/control/scripts/run-review.sh
```

输出文件：

```text
.agent/reviews/review-input.md
.agent/reviews/review-output.md
```

## 卡住时怎么判断

如果终端停在：

```text
REVIEW_HTTP_REQUEST: ...
```

通常是模型响应慢、网络慢或 API 没有返回。可以另开终端看输出文件是否增长：

```bash
tail -f .agent/reviews/review-output.md
```

## AI 助手最终处理

独立二审输出后，在 AI 助手里说：

```text
读取 .agent/reviews/review-output.md，判断哪些问题成立。
成立的问题请修复并跑测试；不成立的问题说明原因。
```

## 注意

- 独立二审结果不是业务事实。
- 独立二审不能替代 OpenSpec。
- 独立二审不能替代测试。
- 所有修复仍由 AI 助手按项目规则和用户确认执行。
