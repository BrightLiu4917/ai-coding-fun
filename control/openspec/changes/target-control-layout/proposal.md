# 变更提案：目标项目安装输出目录收敛

## 项目背景

控制系统仓库自身已经将主要资产收敛到 `control/` 目录，但安装到目标业务项目后，当前 profile 仍会把 `agents/`、`docs/`、`scripts/`、`templates/`、`tools/`、`profiles/` 和 `openspec/` 直接铺到目标项目根目录。用户希望目标业务项目也能保持根目录清爽，把控制系统相关文件统一放到一个目录下管理。

## 项目目标

- 调整安装到目标业务项目后的输出结构。
- 保留目标项目根目录 `AGENTS.md` 作为 Codex 自动发现入口。
- 将控制系统规则、agent、脚本、模板、工具和 profile 统一放到目标项目的控制目录。
- 明确 OpenSpec 和上下文文件是否仍保留在目标项目根目录，避免把业务事实源和工具资产混淆。
- 保持现有安装脚本可 dry-run、可备份、可回滚。

## 核心问题

- 当前安装输出会占用目标业务项目根目录，和业务源码目录、业务文档目录混在一起。
- 如果直接把所有文件移入隐藏目录，Codex 自动发现和人工入口可能变差。
- OpenSpec 是业务事实源，是否应与工具资产一起收纳需要用户确认。
- `scripts/ai-dev.sh`、`scripts/run-tests.sh` 等目标项目命令路径会变化，必须同步更新入口和文档。

## 功能范围

- 范围内：设计目标项目安装后的目录结构。
- 范围内：更新 profile 安装清单和安装脚本路径映射。
- 范围内：更新目标项目 `AGENTS.md` 模板，让它指向新控制目录。
- 范围内：更新 `ai-dev.sh`、检查脚本和 README 中面向目标项目的命令说明。
- 范围内：提供旧结构到新结构的兼容提示和回滚方案。

## 核心价值

- 目标业务项目根目录更干净。
- 控制系统资产边界更清楚。
- 后续卸载、升级、版本对比和团队审查更容易。

## 变更内容

- 新增：目标项目控制资产目录规则。
- 修改：profile 文件清单。
- 修改：安装脚本对源路径和目标路径的映射逻辑。
- 修改：目标项目 `AGENTS.md` 模板中的事实源路径。
- 修改：目标项目命令说明和检查脚本调用方式。
- 废弃：目标项目根目录直接展开多数控制系统工具资产的安装方式。

## 非目标

- 不修改控制系统仓库自身的 `control/` 结构。
- 不修改业务源码、数据库、API、权限、页面或状态流转。
- 不自动迁移已经安装到业务项目中的旧结构。
- 不引入新依赖。

## 影响

- 产品/业务：目标项目根目录更清晰，不改变业务规则。
- 交互和界面：不涉及页面交互。
- 前端：不涉及前端运行时代码。
- 接口：不涉及运行时 API。
- 后端：不涉及后端运行时代码。
- 数据库：不涉及数据库。
- 测试：需要验证安装 dry-run、新项目安装、检查脚本和目标项目入口。
- 发布：需要明确旧结构兼容和回滚策略。

## 影响范围

```yaml
affected_files:
  - control/AGENTS.md
  - control/README.md
  - control/profiles
  - control/scripts
  - control/templates
  - control/docs
  - control/openspec
affected_tables:
  - none
affected_apis:
  - none
affected_pages:
  - none
affected_agents:
  - agent-openspec
  - agent-architect
  - agent-release
```

## 风险说明

- 安装输出结构变化会影响用户已有命令习惯。
- profile 如果只改目标路径、不改脚本检查路径，会导致安装后检查失败。
- OpenSpec 是否放入控制目录会影响“业务事实源可见性”，需要用户确认。
- 目标项目根目录 `AGENTS.md` 必须保留，否则 Codex 自动发现入口可能变差。

## 待确认问题

### 问题 1：目标项目控制目录名称
- 需要确认：已确认使用 `.ai-control/control/` 作为目标业务项目中统一管理控制系统资产的目录。
- 建议方案：使用 `.ai-control/control/` 存放工具资产，保留 `.ai-control/project.env` 和 `.ai-control/project-profile.md` 作为项目画像。
- 推荐原因：`.ai-control/` 已经是目标项目适配层，继续放控制资产语义统一；增加 `control/` 子目录可避免和项目画像文件混在一起。
- 影响范围：影响安装目标路径、`AGENTS.md` 模板、检查脚本和用户命令。
- 可选方案：使用 `.ai-control/` 直接存放全部控制资产；或使用根目录 `control/`。
- 默认处理：已确认，按 `.ai-control/control/` 进入实现。

### 问题 2：OpenSpec 是否进入控制目录
- 需要确认：已确认目标业务项目的 `openspec/` 不迁入统一目录，继续保留根目录。
- 建议方案：`openspec/` 和 `CONTEXT.md` / `CONTEXT-MAP.md` 暂时保留目标项目根目录。
- 推荐原因：OpenSpec 和上下文是业务事实源，不只是工具资产；保留根目录更容易被业务团队和 Codex 发现。
- 影响范围：影响事实源路径、AGENTS 模板、OpenSpec 检查脚本和用户工作流。
- 可选方案：把 `openspec/`、`CONTEXT.md` 和 `CONTEXT-MAP.md` 一并迁入 `.ai-control/control/`。
- 默认处理：已确认，`openspec/`、`CONTEXT.md` 和 `CONTEXT-MAP.md` 保留目标项目根目录。

### 问题 3：旧结构兼容策略
- 需要确认：已确认本变更只面向新用户和新安装，不处理旧结构迁移。
- 建议方案：新安装默认使用新结构；已存在旧结构时不做自动迁移。
- 推荐原因：旧项目里的规则文档或脚本可能被用户改过，本次聚焦新安装可以降低风险。
- 影响范围：影响安装脚本、升级说明和回滚方案。
- 可选方案：提供 `--migrate-layout` 自动迁移旧结构。
- 默认处理：已确认，本次只实现新安装输出结构，不自动移动目标项目旧文件。
