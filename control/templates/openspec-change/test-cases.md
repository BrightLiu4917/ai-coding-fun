# 测试用例

> 本文件在 OpenSpec 设计阶段由测试工程师（`agent-test`）产出，随 change 一起等待用户确认。
> 用例是验收契约：实现必须向用例收敛，执行阶段禁止为迁就实现而修改已确认用例；确需修改时必须重新确认。
> 验收以原始证据为准：自动化用例看 JUnit 报告（测试名含 TC-ID），手动用例的执行结果写入交付说明；不维护状态列。

## 证据约定

- 自动化测试的方法名或 describe 名必须包含用例ID（如 `test_TC01_分页查询`、`TC-02 非法参数`）。
- 发布门禁运行 `test-cases-check.sh --evidence`：直接核对 JUnit 报告——报告存在、无失败、每条非手动用例的 TC-ID 有通过记录。
- 验证方式为“手动”的用例不在门禁核对范围，执行结果由交付说明逐条承载。

## 覆盖要求

- 每个 spec 场景至少一条用例。
- 涉及 API（affected_apis 非 none）时，必须包含异常流用例：参数错误、数据不存在、状态不允许。
- 涉及页面（affected_pages 非 none）时，必须包含权限态、空态、错误态用例。
- 涉及写操作时，必须包含重复提交或并发用例。
