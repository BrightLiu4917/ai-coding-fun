# 测试用例

> 设计阶段由测试工程师产出，随 change 一起确认；实现后回填状态。

## 用例清单

| 用例ID | 关联场景 | 类型 | 前置条件 | 步骤 | 预期结果 | 验证方式 | 状态 |
|--------|----------|------|----------|------|----------|----------|------|
| TC-01 | 按状态筛选用户列表 | 正常流 | 存在启用和禁用用户 | 调用 `GET /api/admin/v1/user/page?status=enabled` | 仅返回启用用户，分页字段正确 | 集成 | 通过 |
| TC-02 | 状态选项加载 | 正常流 | 已登录管理员 | 调用 `GET /api/admin/v1/user/status-options` | 返回全部状态枚举，中文标签 | 单测 | 通过 |
| TC-03 | 非法状态参数 | 异常流 | 已登录管理员 | 以 `status=xxx` 请求分页接口 | 返回参数错误，不返回 500 | 集成 | 通过 |
| TC-04 | 无权限访问 | 权限 | 使用无用户管理权限的账号 | 请求分页接口 | 返回无权限响应，列表页展示权限态 | E2E | 通过 |
| TC-05 | 筛选结果为空 | 边界 | 选择无匹配数据的状态 | 页面执行筛选 | 展示空态文案，不报错 | E2E | 通过 |
| TC-06 | 接口失败反馈 | 异常流 | 模拟接口 500 | 页面执行筛选 | 展示错误态并可重试 | 手动 | 通过 |

- 类型：正常流 / 异常流 / 权限 / 边界 / 兼容性 / 并发
- 验证方式：单测 / 集成 / E2E / 手动
- 状态：已设计 / 通过 / 失败

## 测试命令

## 手动验证步骤

- 模拟分页接口返回 500，确认列表页展示错误态且提供重试入口。
