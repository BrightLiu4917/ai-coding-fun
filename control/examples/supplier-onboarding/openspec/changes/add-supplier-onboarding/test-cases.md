# 测试用例

> 设计阶段由测试工程师产出，随 change 一起确认；验收以 JUnit 报告和交付说明为证据。

## 用例清单

| 用例ID | 关联场景 | 类型 | 前置条件 | 步骤 | 预期结果 | 验证方式 |
|--------|----------|------|----------|------|----------|----------|
| TC-01 | 供应商提交入驻申请 | 正常流 | 已登录供应商账号 | 填写完整资料调用 `POST /api/app/v1/supplier-onboarding/submit` | 申请创建成功，状态为待审核 | 集成 |
| TC-02 | 必填字段缺失 | 异常流 | 已登录供应商账号 | 缺少必填字段提交 | 返回参数错误并提示缺失字段，不落库 | 单测 |
| TC-03 | 重复提交申请 | 并发 | 已存在待审核申请 | 再次提交相同申请 | 返回业务错误，不产生重复数据 | 集成 |
| TC-04 | 查询入驻详情 | 正常流 | 存在已提交申请 | 调用 `GET /api/app/v1/supplier-onboarding/detail` | 返回申请状态和资料 | 集成 |
| TC-05 | 平台端分页审核列表 | 正常流 | 存在多条申请 | 调用 `GET /api/admin/v1/supplier-onboarding/page` | 按提交时间分页返回 | 集成 |
| TC-06 | 无权限访问平台列表 | 权限 | 使用无审核权限账号 | 请求平台端分页接口 | 返回无权限响应，页面展示权限态 | E2E |
| TC-07 | 入驻页空态 | 边界 | 新供应商无任何申请 | 打开 `/supplier/onboarding` | 展示空态引导，不报错 | E2E |
| TC-08 | 提交失败反馈 | 异常流 | 模拟提交接口失败 | 页面提交申请 | 展示错误态，可重试，已填数据不丢失 | 手动 |

- 类型：正常流 / 异常流 / 权限 / 边界 / 兼容性 / 并发
- 验证方式：单测 / 集成 / E2E / 手动

## 测试命令

```bash
bash .ai-control/control/scripts/run-tests.sh
```

## 手动验证步骤

- 模拟提交接口失败，确认错误态展示且表单数据保留。

## 残余风险

- 审核驳回后的重新提交流转在后续 change 覆盖。
