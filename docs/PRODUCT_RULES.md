# 产品规则

## 必须明确
- 目标用户是谁。
- 用户要完成什么任务。
- 当前需求解决什么业务问题。
- 成功指标是什么。
- 功能范围和非范围是什么。
- 是否影响已有用户工作流。

## 禁止事项
- 禁止把实现细节当作产品目标。
- 禁止为了技术方便改变业务流程。
- 禁止发明用户角色、业务目标、权限或通知规则。
- 禁止忽略异常场景、空数据场景和失败场景。

## 输出要求
涉及产品决策时必须说明：
- 用户角色
- 使用场景
- 业务目标
- 成功指标
- 核心流程
- 异常流程
- 非范围
- 待确认问题

## 待确认问题格式

待确认问题必须帮助用户做选择，不能只写“待确认”。每个问题必须包含：

- 需要确认：用户必须拍板的事项。
- 建议方案：Codex 的默认建议。
- 推荐原因：为什么这样更稳、更小或更符合项目。
- 影响范围：影响哪些表、接口、页面、权限、测试或发布。
- 可选方案：其他可选方案，如有。
- 默认处理：用户确认后才按建议进入设计和实现，未确认前不得写成已确认规则。
