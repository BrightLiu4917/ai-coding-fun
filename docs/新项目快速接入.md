# 新项目快速接入

## 方式一：交互式安装

适合第一次使用：

```bash
bash scripts/setup-control-system.sh
```

脚本会询问：

- 项目目录
- 项目名称
- 是否全栈
- 是否 Spring Boot
- 是否 Vue / React
- 是否 gupo 项目
- 是否启用 deepv4

## 方式二：非交互式安装

适合你已经知道项目目录和参数：

```bash
bash scripts/bootstrap-new-project.sh \
  --project-dir /path/to/project \
  --project-name my-project \
  --profile auto \
  --backend api \
  --frontend vue
```

`auto` 会自动识别项目类型，并在目标项目生成：

```text
.ai-control/project.env
.ai-control/project-profile.md
```

## 常见组合

### 普通项目

```bash
bash scripts/bootstrap-new-project.sh \
  --project-dir /path/to/project \
  --profile auto
```

### api + vue 全栈项目

```bash
bash scripts/bootstrap-new-project.sh \
  --project-dir /path/to/project \
  --project-name bidding-system \
  --profile fullstack-admin \
  --backend api \
  --frontend vue
```

### gupo 项目

```bash
bash scripts/bootstrap-new-project.sh \
  --project-dir /path/to/gupo-project \
  --profile gupo \
  --gupo
```

### 启用 deepv4

```bash
bash scripts/bootstrap-new-project.sh \
  --project-dir /path/to/project \
  --profile auto \
  --deepv4
```

安装后编辑：

```text
.agent/deepv4.env
```

填入真实：

```text
DEEPV4_BASE_URL
DEEPV4_API_KEY
DEEPV4_MODEL
```

## OpenSpec CLI 是否必须安装

不必须。默认使用 `scripts/ai-dev.sh` 创建和检查本地 `openspec/`，不依赖 npm 版 OpenSpec CLI。

如果你需要官方 `openspec` 命令，可以额外安装：

```bash
npm install -g @fission-ai/openspec@latest
```

新项目如果要使用官方 CLI，可以在接入控制系统前先执行：

```bash
openspec init
```

已经接入控制系统的项目，不建议盲目再次运行 `openspec init`，避免覆盖或改写已有 `openspec/`、`AGENTS.md` 等文件。

## 第一个需求怎么做

1. 进入目标项目后先初始化项目卡片：

```bash
bash scripts/ai-dev.sh init
```

`init` 会用编号选择访问控制模式：

```text
1) 本服务建设 RBAC
2) 外部系统负责权限
3) 不适用
4) 待确认
```

`init` 还会问是否现在启用 deepv4。启用时输入：

```text
DEEPV4_BASE_URL
DEEPV4_API_KEY
DEEPV4_MODEL
```

脚本会写入 `.agent/deepv4.env`。该文件包含密钥，不要提交。

项目已经初始化过时，默认不会覆盖已有项目卡片和 `.ai-control/project.env`。确实要重写时：

```bash
bash scripts/ai-dev.sh init --force
```

2. 创建 OpenSpec change：

```bash
bash scripts/ai-dev.sh feature add-my-feature
```

已有 change 默认不会覆盖。确实要重生成骨架时：

```bash
bash scripts/ai-dev.sh feature add-my-feature --force
```

3. 在 Codex 里说：

```text
读取 openspec/changes/add-my-feature，帮我做需求预审、架构设计、表结构/API/任务拆分。
```

4. 需求确认后执行：

```bash
bash scripts/ai-dev.sh ready add-my-feature
```

只有输出 `READY_OK` 后再进入实现。

## 注意事项

- 空项目建议先 `git init`。
- 不清楚字段、状态、权限、API 时不要直接写代码。
- 数据库变更必须先 DBA 设计并确认。
- `.ai-control/project.env` 可以提交，用于记录项目画像。
- `.agent/project.env` 和 `.agent/deepv4.env` 不要提交。
